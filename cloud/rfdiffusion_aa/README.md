# RFdiffusionAA cloud package: de-novo pocket around the 2-Nal anchor

Self-contained instructions to run RFdiffusionAA on a GPU cloud host with at least
16 GB (the local 8 GB box is deliberately not used). The goal is to diffuse a protein
backbone around the verified 2-naphthylalanine anchor so that **pocket shape** can
discriminate the ncAA, since the LigandMPNN dry-run showed sequence design cannot.

Read `../../README.md` first for why the target is 2-Nal and not L4F, and what the
pocket actually has to achieve. The short version is below, because it changes what
counts as a good design.

## What a good design looks like

Do not select for a big pocket. A pocket that is merely large admits tryptophan at 76%
volume overlap with 2-Nal and discriminates nothing, which is the L4F mistake in a
different form.

Measured by `../../src/analyze_shape_gap.py`, against the best-mimicking Trp rotamer:

| quantity | value |
|---|---|
| Trp and 2-Nal shared volume | 103.9 A^3, 76% of 2-Nal |
| Trp surplus over 2-Nal | 19.7 A^3 |
| 2-Nal volume Trp cannot fill | 32.5 A^3 |
| indole NE1 to nearest 2-Nal atom | 0.56 A, inside the envelope |

The discrimination lever is the last row. Trp's N-H donor lands essentially on a
naphthalene carbon position, so a pocket complementary to 2-Nal necessarily buries that
donor against apolar surface, which costs 1 to 3 kcal/mol and does not depend on volume.
After designs exist, rank them with `../../src/check_n1_pocket.py`, which reports whether
the residues lining that position are apolar.

RFdiffusionAA has no objective term for this. It conditions on ligand atoms and nothing
else, so the N1 criterion is a selection filter applied after the fact, not something
passed on the command line. Fan out designs and filter.

## What is baked in

Two inputs, both generated by `../../src/prep_rfdiffusion_aa_input.py`:

- **`input_2NAL_pocket.pdb`** (primary). Ligand = the 2-Nal anchor, resname **`NAL`**,
  12 carbons, zero oxygens, with CONECT. Chemistry identical to
  `data/raw/ligand_2NAL.pdb`, which is sha1-pinned and geometry-checked by
  `src/prep_ligand_2nal.py`.
- **`input_L4F_pocket.pdb`** (baseline, kept). Ligand = the L4F anchor, resname **`PFF`**,
  8 carbons plus the single para-F. This is the documented negative control, retained so
  the earlier result stays reproducible. It is not the target.

Both carry a **carrier protein** = scaffold chain A, 172 residues, 1391 atoms. It exists
only so RFdiffusionAA's `process_target()` can build the contig frame from CA atoms. With
the de-novo contig below it is parsed and then discarded by `insert_contig`, which keeps
only the ligand as the motif. This is the upstream 7v11/OQO pattern.

**Verification stamp, from the build:**

```
2NAL  kabsch anchor -> pocket RMSD 0.720 A
      resname NAL, 12 atoms, elements {C: 12}, 0 O, 11 ring bonds        PASS
      carrier contacts under 3.0 A: 8  (min 1.76 A)

L4F   kabsch anchor -> pocket RMSD 0.707 A
      resname PFF, 9 atoms, elements {C: 8, F: 1}, 0 O, 6 ring bonds     PASS
      carrier contacts under 3.0 A: 0  (min 3.14 A)
```

The 2-Nal clashes are expected and harmless here, because the carrier is discarded for a
de-novo contig. They do mean something for the future, though: L4F fitted inside the 4QAE
pocket and 2-Nal does not. **The motif-scaffold fallback is therefore not available on
this scaffold for 2-Nal.** De novo is the only route, which is why no motif refs appear in
the contig.

RFdiffusionAA reads the ligand through OpenBabel (`parse_mol`): atom identity from the
element column, bonds from CONECT and geometry, with no CCD or template lookup. So `NAL`
is only a label that has to match `inference.ligand`, and the fused rings are seen
directly. Nothing to edit.

## One-time setup on the cloud host, about 13 GB plus Apptainer

```bash
git clone --recurse-submodules https://github.com/baker-laboratory/rf_diffusion_all_atom.git
cd rf_diffusion_all_atom
# container (~11.8 GB) and weights (~1.27 GB), both into this repo dir:
wget http://files.ipd.uw.edu/pub/RF-All-Atom/containers/rf_se3_diffusion.sif
wget http://files.ipd.uw.edu/pub/RF-All-Atom/weights/RFDiffusionAA_paper_weights.pt
# Apptainer: https://apptainer.org/docs/admin/main/installation.html
```

## Run

Copy `input_2NAL_pocket.pdb` into the repo's `input/` dir, then run from the repo dir:

```bash
mkdir -p input output/2nal_pocket
cp /path/to/input_2NAL_pocket.pdb input/
apptainer run --nv rf_se3_diffusion.sif -u run_inference.py \
  inference.deterministic=True \
  diffuser.T=100 \
  inference.output_prefix=output/2nal_pocket/des \
  inference.input_pdb=input/input_2NAL_pocket.pdb \
  inference.ligand=NAL \
  contigmap.contigs=[\'130-130\'] \
  inference.num_designs=1 \
  inference.design_startnum=0
```

The repo-integrated runner `../../src/run_rfdiffusion_aa.sh` takes the same parameters and
is preflight-gated.

### Tunables

- `contigmap.contigs=[\'N-N\']` is the pocket length. Start around **130** for 2-Nal, up
  from the 120 used for L4F, because 2-Nal reaches 6.46 A from CB against PHE's 4.28 A and
  needs a deeper cavity. 100 to 160 is sane. Smaller stays more compact and reduces the
  risk of the long-helix failure mode from era 1.
- `inference.num_designs` should be raised once the first design looks sane. The N1 filter
  only has value across a population, so fan out before filtering.
- `diffuser.T` is 100 in the upstream ligand example, up to 200 for more steps.
- `inference.ligand` must match the resname: `NAL` for 2-Nal, `PFF` for the L4F baseline.

### Expected outputs

- `output/2nal_pocket/des_0.pdb` is the design. The backbone is what matters; the sequence
  is meaningless until LigandMPNN runs.
- `des_0_Xt-1_traj.pdb` and `des_0_X0-1_traj.pdb` are trajectories.

## After the backbone exists

1. **Filter on the N1 criterion.** `python src/check_n1_pocket.py --pocket <design.pdb>`
   reports the residues lining the indole-N1 position and whether they are apolar. Discard
   designs that put a donor or acceptor there, since those will satisfy Trp's N-H and
   throw away the discrimination.
2. **LigandMPNN** sequence design on the surviving pockets. The conda env is installed
   locally and runs CPU-only at these sizes. Consider fixing the N1-lining positions to
   apolar residues rather than hoping the model chooses them.
3. **AF2-multimer co-fold** with the validated instrument, `src/prep_multimer.py` then
   `src/run_multimer.sh` then `src/parse_interface.py`. Rank by interface PAE, tie-break
   on iPTM. On an 8 GB GPU this needs the JAX `platform` allocator.
4. **Physics affinity gap, the actual discrimination test.** Score the designed pocket
   against 2-Nal and against **tryptophan** (`data/raw/ligand_TRP.pdb`, built by
   `src/prep_ligand_trp.py`). Trp is the decisive comparator, not PHE. Also score PHE
   (`data/raw/ligand_PHE.pdb`) as the easy baseline. The **gap** is the win condition, not
   raw affinity.
